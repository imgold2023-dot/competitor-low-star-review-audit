Two-hour product QA pass for a small SaaS release

This sample shows the shape of a short paid diagnostic: one flow, ranked issues, evidence notes, and a regression checklist the team can act on.

Sample brief

Test a staging-only workspace invite flow before launch. Use dummy users. Flag bugs, unclear requirements, and follow-up checks. Do not access production data.

Diagnostic Output

1. Flow Map

Admin invites a teammate, teammate accepts the invite, workspace permissions are applied, and billing-sensitive areas stay hidden from non-admin users.

2. Risk Focus

Permissions, expired links, duplicate invites, email mismatch, empty states, loading states, and recovery after failed acceptance.

3. Delivery Note

Seven checks run, three issues found, one requirement question raised, and five regression checks recommended for the next build.

Issue Table

Severity Finding Evidence Suggested Fix
High Accepted invite keeps the user in viewer mode until the page is refreshed. Chrome 125, staging, invite-accept flow, workspace role badge remains "Viewer" after success toast. Refresh local role state after invite acceptance or re-fetch the membership object before redirect.
Medium Expired invite link shows a generic 500-style error instead of a recovery path. Expired token route returns "Something went wrong" with no resend action. Return a specific expired-link state with a "request new invite" path and support copy.
Medium Duplicate invite creates two pending rows for the same email. Admin invites qa+2@example.test twice. Pending table shows two active rows. De-duplicate pending invites by workspace and normalized email; surface the existing invite timestamp.
Low Empty state copy says "No members" while the current admin is visible in the table. Members tab, new workspace, admin account only. Change empty state to "No teammates invited yet" or hide it when one member exists.

Regression Checklist

Permission Checks

  • Admin can invite a member.
  • Viewer cannot open billing settings.
  • Role badge updates immediately after invite acceptance.

Invite Edge Cases

  • Expired token shows a recoverable state.
  • Duplicate invite does not create duplicate pending rows.
  • Email mismatch blocks acceptance with clear copy.

Release Notes

  • Keep this flow in the pre-release smoke list.
  • Add one API or Playwright check after the state refresh bug is fixed.
  • Retest permissions before opening the next beta group.

Boundary

This page contains no order form, contact form, payment link, tracker, or login. It is a portfolio sample only. Real work should use the hiring platform's normal proposal, milestone, messaging, and escrow flow. Test data, staging access, public repositories, or minimal reproductions are enough for a first diagnostic. Production credentials, private keys, production cookies, banking information, identity documents, and real customer records are out of scope.
