# 平台安全作品页说明

文件：`services/marketplace-safe.html`

用途：作为 Upwork、Fiverr、Freelancer、Guru、PeoplePerHour、Contra 等自由职业平台资料或 proposal 中的 portfolio 链接。

## 为什么需要单独版本

普通服务页适合独立公开获客，因此包含 GitHub issue 服务请求入口。

但自由职业平台通常要求客户沟通、订单、文件交付和付款留在平台内。为了降低账号与投递风险，平台资料应使用 `marketplace-safe.html`，而不是带外部请求入口的普通服务页。

## 页面特点

- 只展示能力、交付范围、公开作品证明和安全边界。
- 不提供站外联系方式。
- 不提供站外下单、付款、询价或服务请求表单。
- 明确提示：如果客户来自自由职业平台，应在该平台内沟通、确认范围、创建订单和付款。

## 使用规则

在自由职业平台内：

- 使用 `marketplace-safe.html` 作为作品链接。
- 不引导客户去 GitHub issue、邮箱、社交账号或其他站外渠道提交需求。
- 不要求站外付款。
- 不处理支付凭证、KYC、银行、私钥、生产 cookie、客户数据或私有后台。

在独立公开渠道中：

- 可使用普通服务页 `services/index.html`。
- 可使用 GitHub issue 服务请求表单收集公开、非敏感的小范围需求。

## 当前收入冲刺判断

平台投递优先使用安全作品页，独立公开获客才使用普通服务页。这样可以保留两条路径：

- 平台路径：合规、低触发风险、等待平台审核后手动投递。
- 独立路径：公开 issue 表单接收非敏感需求，但不能替代平台内订单与付款。
