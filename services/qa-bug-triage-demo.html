What I need

Safe test access

A staging URL, test account, dummy data, local setup, or clear screenshots. No production passwords or private customer records.

One narrow slice

Examples: signup to first action, chatbot answer quality, role permissions, checkout in test mode, or one release-critical workflow.

Expected result

A short note on what should happen, what must not happen, and which browser/device matters most for the first pass.

Sample bug table

Severity Area Finding Evidence to attach Next action
High Chatbot reset After clearing a conversation, the assistant still uses stale project context in the next answer. Prompt transcript, browser console timestamp, expected vs actual answer. Retest context reset and add a regression prompt set.
High Role permissions A viewer role can open a disabled admin action through direct navigation. Role name, route, request/response status, screenshot of blocked UI vs allowed route. Block server-side, then add role matrix checks.
Medium Mobile layout The primary action overlaps the empty state on narrow screens after a failed search. Viewport size, screenshot, reproduction steps, affected browser. Fix responsive spacing and add a narrow-width visual check.
Medium API validation The form shows success after the API returns a validation error payload with HTTP 200. Network response body, form state before submit, expected error copy. Treat semantic validation errors as failed submissions.

Delivery shape

Bug report

A ranked table with steps, actual result, expected result, evidence, likely user impact, and suggested next action.

Coverage notes

What was tested, what was skipped, which assumptions were made, and where risk remains after the first pass.

Regression checklist

A short list the team can rerun manually or turn into Playwright tests later.

Boundaries

Not included: production secrets, real payment flows, KYC, banking, wallets, private customer data, production cookies, private dashboard scraping, bypassing platform rules, or off-platform payment handling. Payment-like flows are test mode, sandbox, or mocked only.

First paid slice

2 hours

One critical path, 3-6 documented findings if found, and a short coverage note.

4 hours

Two to three linked flows, ranked bugs, regression checklist, and one automation-ready test outline.

After that

If the first slice is useful, expand into Playwright regression tests or a release-readiness checklist.
